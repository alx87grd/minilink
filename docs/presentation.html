The Minilink Backbone

Continuous Core & Functional Purity

Equations are pure mathematical maps: arrays in, arrays out
$$\dot{x} = f(x, u, t; p)$$ $$y = h(x, u, t; p)$$ $$T = \mathrm{tf}(x, u, t; p)$$
Why Functional Purity?
  • Pure Array Maps: Stateless mathematical mappings ($x, u, t \to \dot{x}$). No simulation time cached on self.
  • Classroom-Ready NumPy Default: Pure NumPy/SciPy by default; zero compiler or GPU hurdles for undergraduate control courses.
  • Extensible Leaf Wrapping: Easily wrap legacy C/Python simulators, hardware sensors, or custom dynamics as a System leaf.
  • JAX Compilation Ready: Purity unlocks immediate JIT compilation, machine-precision sensitivities, and GPU batches.
mass_spring_damper.py NumPy / JAX
import numpy as np from minilink import DynamicSystem class MassSpringDamper(DynamicSystem): def __init__(self): super().__init__(n=2, input_dim=1, output_dim=1) def f(self, x, u, t=0, params=None): m, k, b = 1.0, 4.0, 0.3 p, v = x a = (u[0] - b * v - k * p) / m return np.array([v, a]) def h(self, x, u, t=0, params=None): return np.array([x[0]]) plant = MassSpringDamper() plant.x0[0] = 1.0 plant.compute_trajectory(tf=10.0) plant.plot_trajectory()

Differentiable & Accelerated with JAX

Exact analytical derivatives, parallel GPU batches, and gradient-based tuning
$$A = \frac{\partial f}{\partial x}, \quad B = \frac{\partial f}{\partial u}, \quad S_p = \frac{\partial f}{\partial p}$$ $$\nabla_\theta J = \frac{\partial}{\partial \theta} \left[ \int_0^{t_f} g(x, u, t)\, dt + h(x(t_f)) \right]$$
  • Numerical Rigor: Machine-precision analytical sensitivities eliminate finite-difference approximation noise; float64 default verified against analytical baselines.
  • Opt-In Acceleration: Pure NumPy remains the default classroom engine; JAX activates with a single flag (backend="jax") for advanced research.
  • Parallel Batched Rollouts: Hardware-accelerated GPU/TPU rollouts over parameter families via JAX vmap.
  • Plant & Controller Co-Design: Exact gradient descent ($\nabla_\theta J$) optimizes feedback gains and physical plant parameters simultaneously.

The Unified Optimization Boundary

A standardized interface connecting all transcriptions to plug-and-play solvers
$$\min_z \quad J(z; p) \quad \text{s.t.} \quad g(z; p) \le 0, \quad h(z; p) = 0$$
Lego-Block Inter-Compatibility
  • Lower Late: Trajectory collocation, parameter tuning, and policy search all lower to one standard MathematicalProgram.
  • Decoupled Solvers: Problem definitions and solvers are independent Lego blocks. Any solver runs on any program.
  • Pluggable Backends:
    • Gradient / Autodiff: gd, adam, l-bfgs (JAX)
    • Constrained NLP: SciPy (SLSQP), Ipopt (interior-point)

One Problem, Every Planner

A universal optimal control specification solved across paradigms
$$\min_{u(t)} \quad J = \int_0^{t_f} g(x, u, t; p)\, dt + h(x(t_f); p)$$ $$\text{s.t.} \quad \dot{x} = f(x, u, t; p), \quad x(0) = x_0$$ $$x(t) \in X, \quad u(t) \in U, \quad x(t_f) \in X_f$$
  • Unified Formulation: DP, Trajectory Optimization, RRT, and Deep RL solve the exact same mathematical problem.
  • Neural Policies as Systems: A trained neural network policy (NeuralPolicy / MLP) is a standard System: loop = policy @ plant.
  • Objective Benchmarking: Single compare() function evaluates open-loop trajectories, state-feedback, and neural policies on the identical task.

# One problem definition problem = PlanningProblem(sys=plant, x_start=x0, Xf=Xf, cost=cost) # Solved by value iteration, collocation, or RL vi_sol = DynamicProgrammingPlanner(problem).solve() opt_sol = TrajectoryOptimizationPlanner(problem).solve() rl_sol = ReinforcementLearningPlanner(problem).solve() # NeuralPolicy # Every solution policy closes the loop: policy @ plant loop = rl_sol.policy @ plant # Evaluate side-by-side on the identical task print(compare(problem, DP=vi_sol, TrajOpt=opt_sol, RL=rl_sol))

Honest Boundaries: What Minilink is NOT

Disciplined architectural scope: where Minilink excels vs. where specialized tools belong
1. Not a Contact Engine
  • No rigid-body impulse dynamics, mesh collision, or complementarity solvers
  • Design pattern: Wrap external physics engines (MuJoCo, Drake) as leaf blocks in a diagram
2. Dense vs. Sparse NLP
  • Optimized for small-to-mid DoF systems, fixed-step MPC, and batched rollouts
  • For 100-knot trajectory optimization exploiting sparse block Jacobians, CasADi remains superior
3. Continuous-Time Primary
  • Physical dynamics are instantaneous rates ($\dot{x} = f(x,u)$)
  • Discrete clocks sit cleanly in the sibling step algebra (% operator), but continuous physics is the foundation

Key Advantages

A unified, modern foundation for dynamical systems, control, and optimization
  • One Model Across All Domains: Single equation definition ($\dot{x} = f(x,u,t;p)$) connects classical frequency design, optimal control, and reinforcement learning.
  • Zero-Friction Classroom Adoption: Runs out-of-the-box on standard NumPy and 1-click Google Colab with zero compiler or license hurdles on student laptops.
  • Git-Native Diagrams as Code: Pure Python operator algebra (>>, +, @, %) replaces binary .slx block diagrams with clean, reviewable PR diffs.
  • Headless Cloud Scaling: Spin up 10,000 parallel test runs in headless Linux Docker containers on AWS/GCP with zero per-core licensing bottlenecks.
  • Hardware-Accelerated with JAX: Machine-precision autodiff sensitivities, parallel GPU-batched rollouts via vmap, and exact plant-controller co-design ($\nabla_\theta J$).
  • Unified Optimization & Planning Boundary: Standardized MathematicalProgram and PlanningProblem interfaces decouple problems from plug-and-play gradient, NLP, and RL solvers.

The Sky's the Limit

No architectural ceiling: pure array mappings scale from toy plants to billion-parameter frontier models
$$\dot{x} = f(x, u, t; p), \quad p \in \mathbb{R}^{\text{billions}}$$ $$\text{Pure Arrays} \xrightarrow{\text{XLA / SPMD}} \text{Automated Sharding across Cloud Data Centers}$$
Architectural Scalability
  • Pure Array Mappings: Minilink is fundamentally built on pure mathematical maps: arrays in $\to$ arrays out. There is no hardcoded limitation on state dimension or parameter count.
  • Billion-Parameter Neural Blocks: A controller or policy block in Minilink can be an arbitrary JAX neural network module. JAX is the exact engine used to train frontier foundation models.
  • Automated Sharding & Cloud Scale: JAX compiles via XLA with automated array sharding across multi-GPU / multi-TPU cloud data centers (jax.shard_map, SPMD).
  • Zero Architectural Redesign: The identical functional contract that models a 2-state pendulum on a student laptop scales seamlessly to massive neural policies across distributed clusters.
