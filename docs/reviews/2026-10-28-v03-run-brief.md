## 2. Decision rules, in order

1. The rulings, read literally; R166 says they are final.
2. The CONSTITUTION's precedence: purity, closure, the continuous contract, textbook
   readability, single path.
3. The course notes' vocabulary; the shortest clear name; an existing pattern over a new one;
   one path, no alias (R82); when torn, the reversible and smaller option.
4. A choice not covered: decide as the maintainer would, write it in the run's log (§7) with the
   alternative and the commit, and continue. The known ones: the default output stub's type under
   JAX; the open-loop compiled face as the evaluator with no controller or a sibling; the hold
   slots' labels; helper names.

**Never without the maintainer:** removing what no ruling removes; the tuned constants and the
commented-out calls of `examples/` and the notebooks; the CONSTITUTION; the demo pass (K4);
anything on `main`; a force-push; deleting `main`, `dev` or `dev-alex`; a merge with red tests.

## 3. The branch model

- `dev-v0.3` is the integration branch. Step 0 runs on it alone, first.
- Then one branch per lane off `dev-v0.3`: `dev-v0.3-loop`, `dev-v0.3-objects`,
  `dev-v0.3-program`. One agent per lane; a lane's agent may spawn helpers inside its own branch.
- An integrator merges a lane into `dev-v0.3` only when the lane's row tests, its baselines and
  its closeness report are green, in the join order of §4; a merge conflict is resolved by
  merging `dev-v0.3` into the lane branch (never a rebase), with the tests rerun.
- Before every commit and push: `git fetch`; if the branch is behind, stop and say so
  (AGENTS.md, "Before you start"). Every commit message is its subject and body, nothing else.

## 5. The first hour, before any code moves

1. **The environment:** `python -c "import scipy, pytest, jax"`; if it fails,
   `pip install -e ".[dev]" "jax[cpu]"`. Then the "Always before push" row and
   `pytest tests/unittest -q -x` once, green, and the "Regression gates, CI flags" row once,
   green.
2. **The baselines** (R80–R82, AGENTS' recipe): a seeded JSON capture of every branch the run
   touches (each algorithm family, each adapter path, each random-draw path, repeated calls;
   timing fields left out), run twice and `cmp`'d to prove determinism, committed under
   `benchmarks/baselines/` before step 0. Every later closeness report compares against these.
3. **The dry run:** step 0's first rename (`Discretization` → `SampledSystem`, `dt` →
   `sample_period`, every caller, byte-identical), pushed and checked by the gate, to prove the
   loop of edit, lint, test, baseline, commit works in this container.

## 6. The gates, on every push

- The "Always before push" row (lint and format, whole repo).
- The pytest row the change fits (narrow, cross-cutting, or the regression gates for compile,
  `Simulator`, trajopt, MPC and value iteration changes); `--update` only after an intended
  number change, with the JSON diff reviewed.
- **The textbook rule:** every math diff is read beside `planning/dynamic_programming/dp.py`
  and the log says so (AGENTS.md).
- **Byte-identical or a ledger line:** a move or rename stays byte-identical; a restructure
  agrees to `rtol 1e-6`; an intended change is checked by closeness on the same problem and cost
  and gets its line in the log's ledger (§7).
- **One signal pass, one owner:** no second copy of a block's equations, no second owner of the
  schedule (the plan), no `where` firing (a `cond` or the hyperperiod unroll).
- Notebooks: none touched before step 7's last task, then every one moved to the new API and
  debugged, with the `nbstripout` filter set up first and the smoke check run; no new notebook;
  nothing reaches `main`.

## 7. The run's log

One record, `docs/reviews/2026-10-29-v03-run-log.md`, started at the first commit and updated at
every seam, with the 10-24 record's sections: the morning summary (what works, in one script);
the decisions taken without the maintainer, each with the step, the choice, the reason, the
alternative and the commit to revert; the ledger of intended number changes (the same problem
and cost before and after, the relative differences); what was not done or is blocked, and why;
the tests skipped in the container; the textbook-check statement per math diff. The maintainer
reviews it in the morning together with the 10-24 log (R166).
